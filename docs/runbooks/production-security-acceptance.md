# Production security implementation acceptance

Recorded 2026-11-05. This record covers implemented controls and local acceptance evidence. It does not authorize or certify a production deployment. The [rollout requirements](production-rollout.md) retain the remaining live AWS and dedicated-worker gates.

| Control | Executed evidence | Remaining deployment evidence |
| --- | --- | --- |
| Database credentials | Production requires explicit database coordinates and a credential file; missing, conflicting, oversized, invalid and non-regular files fail closed. New connections reload replaced files. PostgreSQL tests verify password rotation and NOLOGIN revocation. | AWS Secrets Manager delivery, rotation and revocation from actual service workloads; existing-session draining. |
| Database compartments | Real temporary PostgreSQL logins execute the allowed application, dispatch and release workflow. Denial checks cover measurement/receipt writes, approval/model access, DDL, trigger disabling, truncation and immutable records. Production API connections and broker startup check compartment privileges. | Dedicated migration ownership, service credentials, database-wide PUBLIC/extension review and network restrictions on the deployed cluster. |
| Cognito authorization | Real RSA-signed test tokens exercise signature, issuer, app-client, audience, token-use, expiry, issued-at, not-before, scope and group checks. JWKS cache/rotation and availability tests pass. HTTP tests retain ownership and independent approval, including actors holding multiple roles. Demo identities fail in production. | Real pool issuance, operational revocation, group administration and provider/network acceptance. |
| Constrained broker | Tests cover approved dispatch intent, fixed image/engine/slot launch, wrong/rootful engine rejection, database serialization, replay, queued reconciliation, missing/malformed/oversized/FIFO receipts and symlink escape. Application credentials cannot insert execution receipts. | Run the broker as UID 10005 against the pinned dedicated Linux rootless engine; verify live daemon, socket, IAM and network constraints. The Mac's shared Docker Desktop engine is not this deployment. |
| Oracle release | A forged SIMULATED status without a committed matching execution receipt fails before outcome files are opened. Actual Linux UID/mount probes deny broker UID 10005 as well as API/planner/trainer access to private outcome files. | Repeat on deployed storage/worker topology, including rootless daemon mounts and any cloud storage credentials. |
| Scientific reference | All five paired six-batch configurations retain the original trajectory hashes after the JWT dependency and broker changes. Contract v1 is preserved; v1.1 records the security dependency change. Vendor and process-fault suites pass. | Retain these gates for future changes and verify hosted CI after publication. |

The local check set contains 72 unit tests, 17 scientific tests, 29 PostgreSQL/HTTP/telemetry integration cases, three vendor golden cases, one approved HTTP workflow, three process-fault cases, five paired reference cases and one Linux mount/UID case. The five reference cases execute ten campaigns and sixty vendor-simulated batches. Ruff, formatting, strict mypy and the dependency audit pass; no known vulnerabilities were reported for auditable third-party dependencies. The existing Starlette/httpx test-client deprecation warning remains unrelated to these controls.

Run `make check`, `make integration`, `make sim`, `make workflow`, `make faults`, `make runtime-image`, `make isolation`, `make reference-workflow` and `make audit` with the documented local prerequisites. The integration target automatically includes the new permission, Cognito and broker cases in hosted CI. Local passage does not establish that these commits have passed a hosted run.

Deployment identifiers and private configuration worksheets are intentionally maintained outside the repository. No AWS account, cluster, user pool, service role, secret or rootless worker has been provisioned by these changes. These unexecuted rollout requirements remain open.
